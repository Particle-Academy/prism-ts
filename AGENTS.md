## A port, not a translation

PHP is the **reference implementation**: the corpus goldens are generated by
executing it. This package must produce the same bytes at the boundary — and
must not look like PHP written in TypeScript.

That tension has a decision:
[0002, idiom vs identity](https://github.com/Particle-Academy/prism-parity/blob/main/docs/decisions/0002-idiom-vs-identity.md).
The short form: **the wire is identical, the ergonomics are native.** Promises,
discriminated unions, strict null checking. A `Result`-shaped union where PHP
throws is idiom; a differently-shaped request body is drift.

## Conformance is not optional and it builds first

```sh
npm run conformance     # runs `npm run build`, then conformance/runner.mjs
```

`conformance/` runs the shared corpus through the built output, not the source.
That is deliberate: a port that passes from `src/` and fails from `dist/` has a
build problem its suite cannot see, and consumers only ever get `dist/`.

If a case fails, the answer is almost never to edit the golden. Goldens come
from executing the reference; a disagreement means either this port is wrong or
the reference changed without the corpus being updated. Both are findings.
Editing the expected bytes to match this port converts a caught bug into an
enforced one across every language.

## The Anthropic provider's five departures from the OpenAI shape

Written down because each one was found by a failing test rather than by reading
documentation, and each is easy to reintroduce while refactoring the two
providers toward a shared helper.

1. **`max_tokens` is required.** OpenAI defaults it; Anthropic rejects the
   request without it.
2. **The system prompt is a top-level field**, not a message with
   `role: "system"`.
3. **Tool calls come back as `tool_use` content blocks**, and `input` is an
   **object** — not a JSON string that needs parsing, as OpenAI's
   `arguments` is.
4. **Tool results are keyed by the CALL id and sent in a `user` turn**, not in a
   dedicated tool role.
5. **Cache tokens are reported separately and must NOT be subtracted** from the
   input count. Subtracting them under-reports usage, which is the kind of bug
   that surfaces as a billing surprise rather than a failing test.

## Gates

```sh
npm test          # vitest run
npm run typecheck # tsc, full project
npm run lint      # eslint
npm run conformance
```

CI runs `tests`, `static` and `conformance`. All four locally before pushing —
`typecheck` covers the whole project while `build` only covers what ships, so a
green build is not a green typecheck.

`agent/server.mjs` (`npm run agent`) is the MCP surface the Lab's team talks to.
It listens on loopback and belongs on loopback: an agent that can run a suite
and spend tokens is remote code execution with a friendly name.

## When core changes

A change to request mapping, response parsing, error codes or value-object
serialisation in PHP core lands in the corpus at the same time. If you find this
port disagreeing with a corpus that was just updated, that is the system
working. If you find it disagreeing with a corpus that was *not* updated, the
finding is in core.
